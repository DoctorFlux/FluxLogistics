## Auction sale chat

The sale feature also loads on Retail 12.1.5.70961, interface 120105, through `FluxLogistics_Standard.toc`. The other four clients load it from the shared manifest. The native formatted sale event carries an optional auction ID. The addon estimates proceeds after the standard 5% cut from a matching sold row or a cached listing. If the client supplies only an active stack quantity, the notice labels the estimated full-stack amount as an upper value. A matched seller invoice supplies the actual payout and any available sold quantity. Matching can use the pending invoice's expected payout time or the completed invoice's arrival time. The display is passive and uses the client's localized notice template with English output in the addon catalog. [Retail source pin](https://github.com/Gethe/wow-ui-source/tree/ab5cb850a3f65e742959e379c4689353a2f4549f) · [Forever sale event](https://github.com/Gethe/wow-ui-source/blob/734f065329cff4992835b01a84f210a297db91b6/Interface/AddOns/Blizzard_APIDocumentationGenerated/AuctionHouseDocumentation.lua#L1262) · [Forever invoice](https://github.com/Gethe/wow-ui-source/blob/734f065329cff4992835b01a84f210a297db91b6/Interface/AddOns/Blizzard_MailFrame/MailFrame.lua#L790) · [Forever payout delay](https://worldofwarcraft.blizzard.com/en-us/news/24315281/wow-forever-hotfixes-november-5-2026).

The secure chat history removal method suppresses the newest native sale notice. The first accepted sale starts a fixed 60-second window. One line per item reports the known sold count, after-cut total, and weighted per-unit amount. An incomplete monetary total is marked `so far` or `payout pending`. A complete matching set of seller invoices can update the summary in place. [Secure chat history methods](https://github.com/Gethe/wow-ui-source/blob/ab5cb850a3f65e742959e379c4689353a2f4549f/Interface/AddOns/Blizzard_SharedXML/ScrollingMessageFrame.lua).

`lua Tests/auction_sales_test.lua` covers the fixed window and timer boundary, weighted prices, unrelated chat, partial stacks, cached listings across reload, and later invoice updates across five client fixtures. Live sale delivery, including auction IDs on partial-stack sales and invoice timing, is pending verification per client.

## Known capability gaps

- Forever's saved craft records confirm native dispatch, carried-output reconciliation and a job crossing professions. The pending client checks include Classic cast ID and result ordering, controller navigation, the action used to switch between professions, and the latest quantity-priced purchase and partial Create paths.
- Recipes with a qualified guaranteed item yield record the lower and upper bounds. When a Classic variable result exceeds the guaranteed output and the client gives no exact outcome quantity, the queue holds the result for review. Legacy recipes without an exact cast spell link remain inspectable. Special crafts, adjustable recipe levels, variable slot quantities, unqualified quality effects and ambiguous stable identities use the native window.
- Cooldown duration and charges are checked from the live recipe at action time. The inspected native cooldown API does not identify a stable shared pool. Multi-recipe shared-pool estimates therefore need qualified pool metadata. The client adapter supplies observed charge and cooldown limits and rechecks before every new action.
- The adapter counts capacity through FluxUI, using carried generic space and known partial stacks with matching links. Recipes that might consume the last ingredient stack or fit only in a specialized bag may need room made before dispatch.
- A profession scan's missing rows never revoke stored recipes. Revocation uses FluxUI's explicit profession-knowledge negative or its saved recipe-removal evidence from a settled owned session. A build without authoritative negative evidence retains its old observations until a fresh owned scan can qualify the current recipe.
