# Implementation and validation

## Desktop evidence

Run the `Tests/*_test.lua` scripts with Lua from the addon root. Run `lua FluxCraft/Tests/AdaptersCatalog.lua` for the catalog and inventory fixture. The restock integration fixture expects the owner source in sibling `_FluxUI`, or the absolute path to `FluxRestockPolicy.lua` as its first argument. The declared owner interface is documented in [integration and rollback](INTEGRATION.md).

The 0.2.48-dev release runs 16 Lua suites, 20 production module syntax checks and four per-package TOC load fixtures. The paired FluxUI fixtures cover shared shopping rows, tier coverage across alternative SKUs, bank and vendor buttons, auction orders, merchant lifecycle, inbox recovery, the Restock tab purchase button and the follow-up Craft button. The installed owner fixtures also cover quantity-depth scans, exact listing approvals and temporary auction targets. Desktop replays through the installed Forever Auctionator 349 source exercise the ordinary recipe output quote, the Shopping tab and the separate recipe, queue and per-material search quantities.

`lua Tests/scale_profile.lua` exercises 1,636 generated learned recipes across two professions. The 22-row viewport reused 22 profit labels and evaluated at most one plan per callback. During a 200-refresh burst with unchanged input it scheduled one callback and reused its prices. A 121-card production plan used 20 visible cards or fewer across three viewport sizes. The desktop fixture also exercised a long Danish label, locked-row geometry and narrow fallback. The game client still needs the corresponding scale and visual checks.

`lua Tests/observed_catalog.lua <FluxLogistics account SavedVariables path>` reads an exported Forever catalogue and reports aggregate checks. The latest 21 November capture contained 145 qualified item recipes across four observed character/profession buckets. With seeded materials, 134 produced exact one-craft plans and 11 were excluded by stored constraints. The planner and queue verified seven cross-profession and ten same-profession producer chains with fixture prices. The same recorded data exercised recipe organization and the From my bags, Best picks and Sell or craft shortlist modes. A paired replay with the native Auctionator cache resolved an estimated profit for 136 recipes. Nine output items lacked a cached AH price. These checks ran on the desktop.

An additional desktop scenario ran production planning, queue and execution on observed Forever recipes 3171 and 3852. It used scripted profession readiness and bag events for the Alchemy prerequisite and Tailoring consumer. The queue waited for the requested profession, required a separate Process action, reserved the confirmed intermediate, ignored pre-craft and duplicate result events, and completed after the final carried output arrived. The player has yet to run that full chain in game.
